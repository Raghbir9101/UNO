2026-08-04 — God Mode & Spectator: Bug Fixes, Layout Cleanup, New Powers
-----------------------------------------------------------------------

BUG FIXES
- Stopped spoofing state.myId for god mode; introduced state.viewId so the
  spectator never sees a false "YOUR TURN" pill, lit pass/draw diamonds, or
  own-turn timer styling.
- Fixed god hand view lagging one action behind: emit god_hands before
  game_state; added Game.applyGodView() and call it from both updateGameState
  and the god_hands socket handler. Removed the crashing Game.render() call
  (render was never exported).
- Made god ◀ ▶ player cycling resilient when the watched player is eliminated
  or spectatingPlayerId was never set (resolveSpectatingPlayer fallback).
- Connected non-god spectators are promoted into room.players when the host
  restarts the game (roomManager.promoteSpectators). God-mode spectators stay
  spectators. Client clears Game.isSpectator on promotion and toasts the result
  (including "Room is full — still spectating").
- Room-browser "Spectate" now uses the same spectateJoin() helper as manual
  join, so it prompts for the god-mode password.

UI / LAYOUT

  pile/diamond/timer metrics (killed the timer's divergent gap).
- Repositioned SPECIAL MODE / UNO! / color / pass diamonds clear of pile cards
  using half-diagonal clearance; clamped button size inside the side margin.
- Split draw-count badge (under deck) and direction arrow (under discard) so
  they no longer stack.
- Rebuilt the god-mode bar as a measured glass pill just above the hand, with
  ◀ ▶ hit rects outside the pill.

NEW FEATURES
- God Mode Fine: tapping UNO opens a player picker; server god_fine draws +2
  for any player at any time, emits uno_caught attributed to a random other
  player, and privately acks the god with the real story.
- God Mode Give Card: new 🃏 button + modal to mint any valid card into any
  player's hand via god_give_card / giveCardToPlayer(). Silent for other
  players (no player_drew toast/animation); only the receiver's hand updates.

2026-08-05 — Fix: God Mode lost after refresh / reconnect
--------------------------------------------------------

SYMPTOM
Joining as a God Mode spectator sometimes rendered the plain spectator view
(all seats as opponents, no revealed hand, no God Mode bar), typically right
after the "Reconnected successfully" toast.

ROOT CAUSES
1. The page-refresh auto-reconnect handler in public/main.js never applied
   res.isSpectator / res.isGodMode. A reload wipes the in-memory flags, so the
   client treated an acknowledged god spectator as a normal player and ignored
   the incoming god_hands payload.
2. roomManager.joinRoom() only matched a stored playerId when the seat was
   already flagged disconnected. On a fast refresh the browser reconnects before
   the server processes the old socket's disconnect, so the lookup missed and a
   brand-new spectator seat was minted with isGodMode = false.
3. The persisted session never recorded spectator/god status, so the reconnect
   could not re-announce the god password when a new seat was unavoidable.

FIXES
- Refresh reconnect now applies the server's isSpectator / isGodMode, enters the
  game for spectators (not just reconnected players), calls Game.applyGodView()
  after seating players, and reports god status in its toast.
- joinRoom() matches a supplied playerId regardless of connected state (holding
  the id is already the credential), so a refresh reuses the same seat with its
  god flag intact.
- Added persistSession() so roomCode/playerId/nickname plus isSpectator and
  isGodMode are stored together; the reconnect re-sends the god password.
- If a seat truly expired while the game runs, the reconnect now offers the
  spectate flow instead of dropping the user back to the lobby.

- public/main.js, server/roomManager.js, WORKLOG.txt
